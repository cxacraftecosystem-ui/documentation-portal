# The offline trace engine: where it came from, and how to tell if it has drifted

The raster-to-SVG engine in this repository is **vendored twice** — once as TypeScript the browser
runs (`frontend/lib/trace/`), once as Kotlin the handset runs (`android/core-imaging`,
`core-vector`, `core-pipeline`, `core-export`). Neither is written here and neither should be edited
here without recording it below.

## Provenance

| | |
|---|---|
| **Copied from** | `designer-portal`, commit `4e2aee3` (`4e2aee38dc7aeee5528941249ecbb4625a6912af`), on 2026-09-14 |
| **Which itself vendored from** | `F:/Offline-Tracer` (Kotlin, taken 2026-08-27) and `D:/Offline-Tracer` (TypeScript). **Neither is a git repository**, so no upstream commit hash exists for either — the manifests are the only identity these files have. |
| **How this copy was taken** | Directory copy, then `diff -rq` against the designer tree for every module and for `frontend/lib/trace/`, `docs/fixtures/` and the four `build.gradle.kts` files. Zero differences. |
| **What is deliberately NOT here** | `:core-native`, the fifth upstream module — an optional SIMD accelerator. `:core-imaging` holds the reference implementation of every kernel in it, and upstream records that deleting it "would cost speed and change no output". It would mean NDK toolchains and per-ABI native builds for a trace nobody has yet measured as too slow. |

## How to check for drift

Both manifests hash **raw bytes**, so the vendored trees are pinned to LF in `.gitattributes` — see
the block there. Without that pin every digest mismatches on a Windows checkout while the files are
in fact correct.

```sh
# From the repository root. Paths in the Kotlin manifest are repo-root relative; paths in the
# TypeScript one are relative to frontend/lib/trace/.
while read -r sha path; do
  case "$sha" in \#*|"") continue;; esac
  [ -f "$path" ] || { echo "MISSING $path"; continue; }
  [ "$(sha256sum "$path" | cut -d' ' -f1)" = "$sha" ] || echo "DIFFERS $path"
done < <(grep -vE '^#|^$' android/UPSTREAM-MANIFEST-KOTLIN.txt)
```

## Known drift from the ORIGINAL upstream manifest, and why it is not an error

Three TypeScript files do **not** match `frontend/lib/trace/UPSTREAM-MANIFEST.txt`:

- `engine/classify.ts`
- `engine/pipeline.ts`
- `engine/simplify.ts`

They were modified in the designer portal by commit `9ff1232` — *"Build Sketches & Prototypes, make
the database provider-agnostic, and fix the classes behind the bugs"* — and that manifest was never
regenerated there. **This copy carries those fixes deliberately**: the designer's engine, bugs fixed,
is the thing being ported, not the pristine upstream. The manifest is left untouched rather than
regenerated because it records what UPSTREAM was, which is a different question from what we ship,
and rewriting it would destroy the only evidence that the three files were ever changed.

So the correct reading of a drift check today is: **three named files differ and are accounted for
here; a fourth would be news.**

## The one mechanical check that the two engines agree

`:core-pipeline`'s `ParityTest` replays the three fixtures in `docs/fixtures/` — generated by the
**TypeScript** engine — through the **Kotlin** and asserts the same numbers, stage by stage. It is
the only thing in this repository that can catch the handset and the browser drawing different
things. Measured on the day this landed: 760 tests across the four modules, 0 failures, including
all four `ParityTest` cases.

```sh
cd android && ./gradlew :core-imaging:test :core-vector:test :core-pipeline:test :core-export:test
```
