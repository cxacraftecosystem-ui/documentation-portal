# UI/UX audit — 2026-10-16

The owner asked "see what else remains from a UI/UX perspective". This document answers that for the
documentation portal (Field Repository), on the web and on Android. It changes no code. Each finding
carries the fix it proposes; the fixes will land on this branch (`feature/ux-fixes`).

The designer portal has its own audit at `designer-portal/docs/UX_AUDIT_2026-10-16.md`, on its own
`feature/ux-fixes` branch. A finding marked **[both]** is the same defect in both portals, so the fix
can be made once and ported. The designer document names its twin.

## Scope and method

| | |
|---|---|
| Branch audited | `origin/main` at `1128eb8`, the commit this branch starts from. Every `file:line` below is against it. |
| Web | Production build (`next build && next start`) against this repository's backend, running against a **throwaway local database** (`docportal_ux` in the `designer-portal-pg` container, all migrations applied). `backend/.env` was never read: the backend ran on placeholder credentials and an unreachable storage endpoint. The database was seeded with the master and admin accounts from `scripts/seed_admin.py`, the 2nd-workshop questionnaire from `scripts/seed_questionnaire.py`, and a small fixture set: 3 crafts, 2 workshops, 6 artisans, 4 products, 2 processes, 3 tools and one researcher. Playwright walked 43 routes at 1440px and 390px (96 page loads) as master admin and as researcher. Every load ran axe-core (WCAG 2.1 A/AA) and measured horizontal overflow, touch targets and time-to-settled. |
| Dark mode | Signed-in pages re-sync the theme from `/preferences/me`, so dark mode was forced on `<html data-theme="dark">` after load and re-checked with axe's contrast rule (5 screens). |
| Android | No device and no system image were available, so the Compose code was read instead. Paths below drop the prefix `android/app/src/main/java/com/fieldrepository/app/`. Android findings are not confirmed on a device; the P0 says so. |
| Excluded | Work in flight elsewhere: the Android top search header and hamburger, accounts and passwords, offline storage, and Aadhaar (hidden by flags). |
| Screenshots | `ux-shots.local/` at the repository root. The `*.local` rule in `.gitignore` ignores it, so the screenshots are not committed. Each finding names its file. A `<name>.txt` beside each `.png` holds the page's rendered text. |

## Load timings (web, localhost)

Time from navigation until the network went idle and no "Loading…" text remained. Every screen
settled in under 2 s. The slowest were Map (1.7 s), Dashboard (1.5 s), artisan edit (1.4 s) and
Questionnaire (1.2 s); the median was 0.9 s. The fixture set is small, so these numbers say nothing
about a production-sized corpus.

## Top issues

1. **DC-A01** (P0, Android): "Take photo" and "Record video" on every record form very likely crash when camera permission is missing.
2. **DC-01** (P1, web) **[both]**: every optional `Field` draws a red asterisk. Screens show "NOTE (OPTIONAL) \*" and "NOTE FOR THE ADMIN (OPTIONAL) \*".
3. **DC-A02 / DC-A03** (P1, Android): about 70 places show raw "HTTP 403 Forbidden" text, and they do it through one unstyled line at the foot of the page.
4. **DC-02** (P1, web) **[both]**: in dark mode, purple links, upload buttons and review row actions drop to 1.7–2.7:1 contrast.
5. **DC-A07** (P1, Android): if admin Settings fails to load, Save writes the defaults over the server's settings.
6. **DC-A04 / DC-A05 / DC-A18** (P1, Android): failed loads read as "Loading…" or "Fetching…" forever.
7. **DC-A06** (P1, Android): My Activity says "You haven't recorded anything yet" when the load failed. It also drops a researcher's older records once the repository passes 100 of a type.
8. **DC-04 / DC-05** (P1, web): the Do's/Don'ts point boxes and the role picker on `/users` have no accessible name.
9. **DC-A09 / DC-A10 / DC-A11** (P1, Android): picker, export and rich-text copy admits gaps.
10. **DC-06** (P1, web): on a phone the review queue is a 920px table, so the decision buttons sit off-screen.
11. **DC-07** (P1, web) **[both]**: phone touch targets are 16–40px. Dashboard tile buttons are 36px.
12. **DC-A12 / DC-A13 / DC-A14** (P1, Android): legacy colours make media rows and the refine panel unreadable in dark mode, and the video hint invisible in light mode.
13. **DC-A15** (P1, Android) **[both]**: the shared text field has no capitalisation and no IME action, and Name accepts newlines.
14. **DC-08** (P1, web) **[both]**: Gender on a new artisan is pre-set to "Male".
15. **DC-A16** (P1, Android): every form with media asks for all six permissions the moment it opens.

## Web findings

### DC-01 · P1 · Every form built on `Field` · Web **[both]**

- **Screenshot:** `ux-shots.local/workshop-access_manage-1440.png`, `workshop-access_request-1440.png`, `sharing-1440.png`, `settings-1440.png`, `artisans_new-1440.png`
- **Where:** `frontend/components/ui/RequiredMark.tsx:69` defines `function RequiredMark({ when = true })`. `frontend/components/FormControls.tsx:39` calls it as `<RequiredMark when={required} />`.
- **What:** a `Field` that never sets `required` passes `undefined`. The default parameter turns that `undefined` into `true`, so all 81 of these call sites draw the asterisk. Examples are `frontend/components/settings/WorkshopAccessQueuePanel.tsx:188` ("Note back to them (optional)") and `WorkshopRosterPanel.tsx:398` ("Note (optional)"). On the artisan form, Email, Gender and Status all read as mandatory. A field team that believes every box is required will invent answers.
- **Fix:** change the call to `when={required === true}` in `Field`. Add a unit assertion that a `Field` with no `required` renders no mark. Port the same change to the designer portal (DW-02).

### DC-02 · P1 · Dark mode: links, upload buttons, row actions, amber notes · Web **[both]**

- **Screenshots:** `ux-shots.local/dark2_review-1440.png`, `dark2_dashboard-390.png`, `dark2_questionnaire-390.png`, `dark2_artisan-new-1440.png`, `dark2_map-390.png`
- **Where:**
  - `frontend/components/RowActions.tsx:21` (`edit`) has text at 1.73:1. `:24` (`danger`) is 2.74:1. `:27` (`positive`) is 3.5:1.
  - `frontend/app/globals.css:459` (`.file-trigger`, `text-purple-700`) is 2.31:1.
  - Bare `text-purple-700` links measure 2.31:1 on cards, for example the dashboard's recent submissions. The map's place links measure 2.18:1.
  - `text-amber-800` notes on cards, such as the late-submission line under Workshop and the questionnaire notes, measure 2.48:1.
- **What:** purple, red, success and amber are literal colours that do not invert, and none of them has a dark pair.
- **Fix:**
  - Add `dark:` pairs to the `RowActions` tones and to `.file-trigger`.
  - Add a link recipe, `text-purple-700 dark:text-purple-300`.
  - Use `dark:text-amber-200` for amber notes on cards.
  - Add a forced-dark axe pass to `e2e/`.

### DC-03 · P1 · Real content drawn in `text-ink-300` (2.4:1) · Web **[both]**

### DC-04 · P1 · Artisan form → Do's / Don'ts point boxes have no name · Web

### DC-05 · P1 · Users → role picker has no name · Web

- **Screenshot:** `ux-shots.local/users-1440.png`, `users-390.png`
- **Where:** `frontend/app/(protected)/users/page.tsx:372` (`<select className="field-input max-w-44" value={user.role} …>`)
- **What:** each row's role `<select>` is announced as "combo box" with no name and no person. axe reports `select-name`. Changing a role writes immediately, so the control needs a name.

### DC-06 · P1 · Phone: the review queue is a 920px table · Web

## Android findings

Paths below are relative to `android/app/src/main/java/com/fieldrepository/app/`.

### P0

#### DC-A01 · P0 · Record forms, media capture → Take photo / Record video · Android

- **Where:** `MainActivity.kt:5050-5054` (photo) and `:5066-5070`, `:5078-5082` (video). The same pattern repeats at `:5161`, `:5178` and `:12061`.
- **What:** each button runs `permissionLauncher.launch(requiredAndroidPermissions())` and then calls `takePhoto.launch(uri)` immediately, with an empty callback. `CAMERA` is declared in the manifest. If the permission has not been granted, starting `ACTION_IMAGE_CAPTURE` throws `SecurityException`, and nothing catches it. **This needs confirming on a device.** The designer portal has the same defect (DA-01).
- **Fix:** request `CAMERA` on its own and launch capture from the result callback. If the request is refused, offer "attach from gallery".
